# Як працювати в цьому репозиторії кільком сесіям одночасно

Правила для агентів (і людей), які ведуть паралельні гілки. Мета: дві сесії, що працюють одночасно,
не конфліктують у тих самих рядках, а гра на основному сайті змінюється лише через перевірений PR.

## 1. Гілки й PR
- Одна задача = одна гілка = один PR. Ім'я гілки дає середовище сесії; пушити лише у свою гілку.
- Гра змінюється **лише через PR**. Зливає PR власник; агент PR не зливає й не закриває чужі.
- Кожна гілка має превʼю: `https://archigreen55-prog.github.io/nocturne-vr/preview/<гілка>/`
  (збирається GitHub Actions після пушу).
- **Стопка PR.** Якщо твоя гілка стоїть на чужій, ще не злитій гілці: PR відкривається з базою =
  та гілка, а перший рядок опису — «Зливати ТІЛЬКИ після PR №N». Нові коміти тієї гілки вмерджуй до
  себе (merge, не rebase чужої історії); чужу гілку не змінюй. Коли базову гілку злили — перебазуй
  свою на `main` і зміни базу PR на `main`.
- Історію чужої гілки не переписувати (без rebase, amend, force-push). Свою — за потреби, з
  `--force-with-lease`.

## 2. Порядок злиття
Злиття — в оголошеному порядку. Перед злиттям гілку оновлюють з `main` (або з гілки, на якій вона
стоїть), ставлять версію (§5) і проганяють повний `npm test`.

Поточний порядок (жовтень 2026):
1. PR №4 (`ccr-09a5cdf3-8iki2i`);
2. PR підготовки до паралельної роботи + готовності для гравців (`ccr-fcca8102-6hd7hf`);
3. «Біг»;
4. «Маєток».

## 3. Хто що чіпає
Код розкладено так, щоб кожна задача додавала **свої файли** і лише 1–2 рядки в спільних місцях.

| Що | Де | Правило |
|---|---|---|
| Системи гри | `src/systems/<система>.js` | нова система = новий файл; існуючу змінює лише той, чия це задача |
| Реєстр систем | `src/systems/index.js` | **спільне місце**: один рядок на систему; позиція в списку = порядок |
| Спільний стан | `src/systems/state.js` | нові поля — лише якщо їх читають кілька систем; інакше стан тримай у своєму модулі |
| Числа (баланс) | `src/config/<тема>.js` | нова тема = новий файл + рядок у `src/config/index.js`; **баланс одночасно править лише одна сесія** |
| Тексти для гравця | `src/i18n/uk.js` | лише у своєму розділі (новий розділ — для нової задачі); у коді — `S.<розділ>.<ключ>` |
| Назва гри | `src/i18n/name.js` | одна константа; змінює лише власник |
| Стилі телефона | `src/ui/phone.css` | свій блок з коментарем-заголовком |
| Стартовий екран | `index.html` | **спільне місце**: мінімум розмітки, тексти — ключами `data-t` |
| Тести | `tests/<тема>.test.mjs` | свій файл; раннер знаходить його сам |
| Версія | `version.json`, `index.html`, `sw.js` | лише через `tools/bump-version.mjs` (§5) |

Спільні місця (`src/systems/index.js`, `src/config/index.js`, `src/i18n/uk.js`, `index.html`): зміна —
кілька рядків, і вона перелічена в описі PR. Конфлікт у них — суміжні рядки; зливається, лишаючи обидва.

## 4. Як додати
- **Систему:** файл `src/systems/<назва>.js` з `export const <назва> = { id, init(), pre(), input(), act(), world(), result(), present(), frame() }`
  (усе необов'язкове; що означає кожна фаза — у коментарі `src/systems/index.js`) + один рядок у `SYSTEMS`.
  Спільний стан — `G` з `src/systems/state.js`. `src/main.js` по суті не редагується.
- **Числа:** `src/config/<тема>.js` (`export const <ключ> = { … }`) + ключ у `CFG` у `src/config/index.js`.
- **Тексти:** ключ у `src/i18n/uk.js`; тексти з числами — функції `(n) => \`… ${n} …\``; у HTML — `data-t="ключ"`.
  Тест `tests/i18n.test.mjs` падає, якщо в коді поза `src/i18n/` з'явився текст українською.
  Інша мова — один файл `src/i18n/<код>.js` з тими самими ключами (`?lang=<код>`).
- **Тести:** `tests/<тема>.test.mjs`, імпорт спільного з `./runner.mjs`.

## 5. Версії при паралельних гілках
- Версію ставить **лише** `node tools/bump-version.mjs <версія>`: він же переписує `?v=` модулів і
  стилів, захист від старої сторінки, список файлів service worker і назву гри в статичних файлах.
- **У робочій гілці:** `<версія бази>.<мітка гілки>.<n>`, наприклад `0.6.0-pre.9.w0.1`,
  `0.6.0-pre.10.run.2`. Так дві гілки ніколи не мають однакової версії на превʼю.
- **Перед злиттям** (після оновлення з `main`): наступна `0.6.0-pre.N` від версії `main`.
- Версії порівнюються лише на рівність (не «більше / менше»): будь-яка нова версія — це нові адреси
  модулів, новий кеш service worker. Це перевіряє `tests/version.test.mjs`.
- Конфлікт у згенерованих частинах (`version.json`, import map і `PAGE_VERSION` в `index.html`,
  `VERSION` / `FILES` у `sw.js`): не правити руками — взяти будь-який бік і перезапустити `bump-version`.

## 6. Три режими
Кожна дія описується й перевіряється для трьох режимів: **VR** (шолом), **телефон**, **ПК**. VR без
шолома перевіряється в емуляторі (`tests/vr.test.mjs`): це ловить поломки коду, не відчуття.

## 7. Перевірка перед пушем
- `npm test` — повний прогін (≈ 7 хв), зелений. Не запускай інші важкі задачі паралельно: частина
  тестів чутлива до швидкості кадрів.
- `ONLY=слово npm test` — тести, у назві яких є слово; `FILE=тема[,тема] npm test` — файли;
  `LIST=1 npm test` — список назв.
- Рефакторинг «без зміни поведінки» доводиться знімком: `node tools/snapshot.mjs before.json --root <копія старого коміту>`,
  `node tools/snapshot.mjs after.json`, `node tools/snapshot.mjs --diff before.json after.json` (тексти,
  конфіг, детермінований слід симуляції, DOM, скриншоти).
- Тест не вимикати й не пропускати, щоб стало зелено; нестабільний тест — виправити.

## 8. Коміти
- Комітити лише свої файли, поіменно (`git add <файли>`), без `git add -A`.
- `user.email` — локальний no-reply GitHub (не глобальний конфіг).
- Без секретів (ключі, токени, паролі) і без особистих email у файлах.
- Документи з планами й звітами живуть в окремому приватному репозиторії; у цей (публічний) їх не кладуть.
